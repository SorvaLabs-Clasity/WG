GitHub Control Hub

Questions about our GitHub organization, already answered

A desktop app that watches the organization in the background, so the answers are waiting when you open it rather than gathered while you wait.

Most of them cannot be answered on github.com without opening one repository at a time. "Everything Sarah can reach" has no page. You would check her teams, then every repository she is on directly, then remember that organization owners have admin everywhere anyway.

Where they live

Eight tabs. These are the five you will see today.

Overview

Cards you choose, each answering one question. Add, edit or remove them.

Access

Every person and team, and what each can reach. Directly, through a team, or by running the organization.

Security

Branch protection, rulesets, secret scanning, vulnerable dependencies.

Vulnerabilities

Dependabot advisories, Renovate's open update pull requests, and who gets emailed about either.

Activity

Everything that changed, whether it happened here or on github.com. Thirteen months, with an undo where the change came from this app.

Three things that make it useful

It notices changes nobody announced. Someone removes branch protection on github.com at two in the morning. Within seconds it is in the activity log with their name on it, and an email goes out if that is something we asked to be told about. Nobody has to be watching.

It tells you without being asked. Any card can carry an alarm: set a threshold, name a group of people, and an email goes out when the number crosses it and again when it recovers. Security events do not wait for a threshold at all. A repository going public, branch protection disappearing, a ruleset deleted, an admin added: those are emailed within seconds of happening.

It changes nothing on its own. Every write is something a person pressed, recorded with their name, and mostly undoable. The AWS guardrails are set to report by default and only enforce where somebody chose that, rule by rule.

Turn it off tomorrow and GitHub is exactly as it is now. It reads far more than it writes, and nothing depends on it running.

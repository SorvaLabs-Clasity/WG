Running order

Each beat names what to click. If a beat runs long, drop beat 6 before anything else; it is the most self-explanatory.

0:00 · 2m

Open cold, on purpose

Overview

Launch the app in front of them rather than having it already open. The point is how fast it is, and that only lands if they see it start.

  • Sign in with Continue as … to show it remembered the last account.
  • Let the Overview draw. Do not narrate while it loads, it will be finished before you finish the sentence.
  • Point at the freshness line under the cards: Updated 3 minutes ago

These numbers were worked out in the background a few minutes ago. Nothing is being fetched while you wait.

0:02 · 5m

Three cards that find real problems

Overview

Do not tour every card. Open three, in this order, because each one raises the next question.

  • Repos with no protected branch at all. Click through to the table. The finding everybody understands without explanation: anyone with write can push straight to the default branch, no review, no record.
  • Repos with no push in N months. Change the months parameter live to show the threshold is yours. Note the rows that read Never pushed to: repositories created and then abandoned without a single commit.
  • Repos exposed through vulnerable package(s). Type a package name and get the list back. This is the card that gets a reaction, because it is the question people actually ask at four in the afternoon when an advisory lands.

Every card is a question you can change or delete. These are the ones I picked; you will want different ones.

0:07 · 4m

Follow one person through

Access

The strongest single moment in the demo. Pick a real person, ideally someone in the room.

  • Click their name. Every repository they can reach, on one screen.
  • Point at the how column: direct via team org owner
  • Click a team and show the repositories that team grants access to.
  • Show the count of outside collaborators and people with personal grants at the top.

On github.com this is one repository at a time, and there is no page that answers it for a person.

0:11 · 4m

What has been happening

Activity

Open on Statistics, not on the table. The shape first, the rows second.

  • Point at the chart and switch Compare to Compose. Same events, two questions: which stream is busiest, and what a given day was made of.
  • Change the window to 30 days. Note busiest hour and busiest day, in your own timezone.
  • Switch to Events. Point at the badge top right: Receiving events. Every row here arrived by webhook within seconds of happening, with the actor's name on it.
  • Open any row to show what actually changed, field by field.

Nobody had to be watching. This is recorded whether the change was made in this app or on github.com, and it is kept for thirteen months.

Then the flip side: find a row this app made and press Undo. That is the difference between a log and a control.

0:15 · 3m

Detailed logging, on and off

Activity

Shows the app has an opinion about noise, which reads well to anyone who has drowned in an audit tool.

  • Top of the Organization stream, flip Detailed GitHub logging on.
  • Open Choose kinds and uncheck Commits pushed.
  • Flip the toggle back off, and say the line that matters.

Turning it off stops recording from here. It does not delete anything already collected.

0:18 · 3m

Who is chasing whom

Pull requests

Drop this beat first if you are running late.

  • Show the list grouped by what is actually blocking each one: approved and unmerged, waiting on review, changes requested, checks failing.
  • Open the settings to show what counts as stale.
  • Pause one pull request, and mute a person, to show the escape hatch exists before anyone asks.

The reminder replaces its own comment each time rather than stacking a new one, so a stale pull request has one comment on it, not eleven.

0:21 · 4m

The AWS half, and the safety catch

AWS

This is where someone senior usually starts paying closer attention. Lead with the restraint, not the capability.

  • Show a rule set to report, and its findings.
  • Say clearly that report is the default and nothing is changed unless a rule is deliberately set to enforce.
  • Press Fix on a single finding. Show that the rule stays on report: it fixed that one resource, once, and did not become an enforcing rule.
  • Show an exclusion, for the resource that is meant to be that way.

Two separate decisions: fix this one thing now, and enforce this rule from now on. The button does the first and never the second.

0:25 · 5m

Questions

Hold this back

Do not fill it. If nothing comes, the answers below are the ones most likely to be asked, and a short one is better than a tour.

If asked

Short answers. Resist expanding them unless pressed.

What does it cost to run?

About seven dollars a month, and most of that is one AWS firewall component we could remove. Measured, not estimated.

Where does our data go?

Our own AWS account. GitHub credentials never leave it and nothing is sent to a third party.

Can it change things in GitHub?

Yes, and only where someone pressed a button. Every write is recorded in the activity log with a name against it, and most can be undone.

What if it breaks or we stop using it?

It reads far more than it writes. Stop running it and GitHub is exactly as it was; nothing depends on it being there.

Will it hit GitHub's rate limits?

At our size it uses about 15% of the hourly allowance at peak. It backs off rather than failing if it ever gets close.

How current are these numbers?

Access data is at most six hours old and usually far fresher, because changes arrive by webhook within seconds. Every screen says how old its answer is.

Who can use it?

Anyone in the organization can look. Changing anything needs membership of an admin team, and the AWS side is a separate team again.

Before you start: have a throwaway repository ready for beat 4, a browser tab already signed in to github.com, and check the Activity badge reads Receiving events. If it does not, the live change will not appear and that beat falls flat.

Deeper material exists if the room wants it: a full architecture briefing and a measured cost and rate-limit breakdown. Do not open either during the demo.
